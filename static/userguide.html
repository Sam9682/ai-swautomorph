Overview

AI-SwAutoMorph is a centralized application deployment and management platform designed for GenAI agents. It provides automated deployment, lifecycle management, and SSO authentication for web applications through multiple interfaces (Web, CLI, API, MCP).

Core Purpose: Enable GenAI agents to autonomously deploy, manage, and access web applications without human intervention.

Getting Started

1. Web Interface

Access the web interface at https://www.swautomorph.com (or your domain)

  • Registration: Create a new account with username, email, password, first name, and last name
  • Login: Access your dashboard with existing credentials
  • Dashboard: View and manage available applications with deployment controls
  • Multi-language: Switch between English (EN) and French (FR)

2. Command Line Interface (CLI)

Use the CLI tool for programmatic access:

# Register a new user
python3 ./scripts/cli.py register --username myuser --email user@example.com --password secure_pass

# List available applications
python3 ./scripts/cli.py list-apps

# Add a new application (admin only)
python3 ./scripts/cli.py add-app --name "My App" --url "https://myapp.swautomorph.com" --description "My Application"

# Initialize database
python3 ./scripts/cli.py init-db

# Check database health
python3 ./scripts/cli.py db-health

# Validate SSO token
python3 ./scripts/cli.py validate-token --token your-sso-token

# Mount S3 storage
python3 ./scripts/cli.py mount-s3fs softfluid /mnt/s3

3. REST API

Integrate with the platform using REST API endpoints:

POST /register
Register a new user
Body: {"username": "user", "email": "user@example.com", "password": "pass", "first_name": "John", "last_name": "Doe"}
POST /login
Authenticate user
Body: {"username": "user", "password": "pass"}
GET /api/applications
List all applications
Returns: Array of application objects with git_url
POST /api/applications
Add new application (admin only)
Body: {"name": "App Name", "description": "Description", "git_url": "https://github.com/user/repo.git"}
GET /api/auth/status
Check authentication status
Returns: {"authenticated": true/false, "sso_token": "token"}
POST /api/deployments
Deploy and manage applications
Body: {"action": "clone|start|stop|restart|ps|logs", "application_name": "MyApp", "git_url": "...", "server_id": 1, "stream": true}
GET /api/servers
List available servers
Returns: Array of server objects with capacity info
POST /api/server/allocate
Allocate server for deployment
Body: {"application_name": "MyApp"}

Application Management

Adding Applications

Applications can be added through:

  • Web dashboard form (admin only)
  • CLI command
  • REST API endpoint
  • MCP protocol
Application Fields:
  • Name: Display name for the application
  • Description: Brief description of the application
  • Git URL: GitHub repository URL for deployment
  • Application Identity: Unique ID assigned automatically

Application Access

Each user gets assigned applications with unique ports:

  • HTTP Port: Calculated based on user ID and app ID
  • HTTPS Port: HTTP port + 1
  • URL Format: https://www.swautomorph.com:[HTTPS_PORT]

Deployment Actions

AI-SwAutoMorph provides comprehensive application lifecycle management through deployment actions:

Available Actions

📥 CLONE

Purpose: Download and prepare application from Git repository

  • Clones the Git repository to deployment directory
  • Copies SSL certificates to application
  • Prepares application for deployment
  • Requires Git URL and server allocation
▶️ START

Purpose: Start the application services

  • Executes deployApp.sh start
  • Starts Docker containers
  • Records billing activity
  • Updates application status to "running"
⏹️ STOP

Purpose: Stop the application services

  • Executes deployApp.sh stop
  • Stops Docker containers
  • Records billing activity
  • Updates application status to "stopped"
🔄 RESTART

Purpose: Restart application services

  • Executes deployApp.sh restart
  • Restarts Docker containers
  • Useful for applying configuration changes
📊 PS (Status)

Purpose: Check application status

  • Executes deployApp.sh ps
  • Returns JSON with container status
  • Shows port information and running state
📋 LOGS

Purpose: View application logs

  • Executes deployApp.sh logs
  • Shows container logs and output
  • Useful for debugging and monitoring

Deployment Flow

1. CLONE → Download application from Git
2. START → Launch application services
3. PS → Verify application is running
4. LOGS → Monitor application output
5. STOP → Stop when needed
6. RESTART → Reload after changes

Virtual Agents

AI-SwAutoMorph includes AI-powered virtual agents to assist with development and operations:

🤖 Virtual Developer

Purpose: Autonomous code modifications and development tasks

  • Code Changes: Modify application source code based on natural language requests
  • Git Integration: Creates branches, commits changes, and pushes to Gitea
  • Testing: Runs test suites before committing changes
  • Deployment: Rebuilds and redeploys applications after changes
Example Usage:
"Add a new API endpoint for user management to the MyApp application"

💡 Virtual DevOps

Purpose: Application deployment and infrastructure management

  • Deployment Actions: START, STOP, RESTART, PS, LOGS
  • Context-Aware: Uses application-specific deployment contexts
  • Natural Language: Understands deployment requests in plain English
  • Automated Execution: Executes commands with proper user context
Example Usage:
"[START] Start the MyApp application" or "Show me the logs for the last 100 lines"

Using Virtual Agents

  1. Access: Click on the Virtual Agents panel (right side of dashboard)
  2. Select Application: Choose the application from dropdown
  3. Choose Agent: Developer for code changes, DevOps for deployment
  4. Send Request: Type your request in natural language
  5. Monitor Progress: Watch real-time streaming output

Virtual Agent Features

  • Streaming Output: Real-time progress updates
  • Auto-Approval: Optional automatic execution of commands
  • Mobile-Friendly: Responsive design for mobile devices
  • Context Injection: Automatically includes user and application context

Database health check (admin only)

Database Structure

The application uses SQLite database with comprehensive tables:

  • users: User accounts with authentication and profile info
  • applications: Available applications with Git URLs
  • user_applications: User-specific app assignments with ports
  • deployments: Deployment tracking with status and paths
  • servers: Multi-server deployment support
  • billing_activities: Usage tracking for cost management
  • application_costs: Cost configuration per application
  • auth_tokens: SSO token management
  • users_logs: User activity logging

Security

Important Security Notes:
  • Auto-generated SECRET_KEY for session security
  • HTTPS with SSL certificates (auto-generated or production)
  • ModSecurity WAF protection with OWASP CRS rules
  • Automated database backups with S3 sync
  • Session-based authentication with SSO token support
  • Admin-only access for sensitive operations

Troubleshooting

Common Issues

Application Deployment

  • "Application not deployed. Clone first": Run CLONE action before START
  • "deployApp.sh not found": Application needs to be cloned first
  • "No standby servers available": All servers at capacity, contact admin
  • Git clone failed: Check Git URL and repository access

Virtual Agents

  • "Q Chat not found": Install qchat: pip install qchat
  • No response from agent: Check network connection and qchat installation
  • Permission errors: Ensure proper deployment directory permissions

System Issues

  • Database not found: Run python3 ./scripts/cli.py init-db
  • Permission denied: Check file permissions: sudo chown -R ubuntu:ubuntu /home/ubuntu/deployments/
  • Port conflicts: Check port usage: sudo netstat -tulpn | grep -E ':(80|443|3000|5000)'
  • SSL certificate issues: Run ./scripts/generate_ssl.sh

Diagnostic Commands

# Check service status
./deployControlPlan.sh ps

# View detailed logs
./deployControlPlan.sh logs

# Database health check
python3 ./scripts/cli.py db-health

# Test API endpoints
curl https://www.swautomorph.com/api/auth/status

# Check Q Chat installation
which qchat && qchat --version

Reset and Recovery

# Stop all services
./deployControlPlan.sh stop

# Complete reset (Docker)
docker-compose down -v
docker system prune -f

# Database recovery
./deployControlPlan.sh --recover_db

# Restart deployment
./deployControlPlan.sh start
